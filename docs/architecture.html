Architecture

How it is built

Seven agents on Google’s Agent Development Kit, running Gemini on Vertex AI, wired together through Cloud Run and Pub/Sub with Firestore as the case record. A letter dropped in a bucket is the only input.

The Cannot column is the design. Firestore has no collection-level IAM, so a per-agent access gateway enforces scoping in code: each agent gets exactly the reads and writes its job needs, and a call outside that set is refused rather than logged. Drafting having no retrieval tool is what makes an invented fact traceable — there is no source it could plausibly have come from.

An adversary, not a reviewer

A reviewer improves a draft. An adversary tries to break one. Verification runs on a separate agent, on a separate model, and resolves every citation and every chart quote against the source document. It can reject and explain; it cannot edit its way to a pass. That asymmetry is the whole reason to believe the letter at the end of the pipeline — and it is what caught a real model overclaiming, twice, on the case the manifest calls easy.

Where ADK ends and our code begins

ADK is in the request path, not in the pitch deck. AdkBackend in agents/adk_fleet.py is a core.llm backend that executes every generative call through an ADK LlmAgent and Runner. Selecting it puts ADK behind all seven agents. The prompts and output schemas are imported from the agent packages rather than restated, so an ADK definition cannot drift from the agent it represents. fleet() composes the seven into a SequentialAgent for adk web, which renders the same definitions the pipeline executes.

The orchestration is deliberately not ADK’s, and that is worth stating rather than glossing:

A Runner drives a session. A session cannot survive six weeks. This pipeline stops at a human gate and resumes later — sometimes much later — from a Firestore document, woken by a scheduler. Two constraints in particular are things a runner-owned control flow would route around: every external effect has to pass through the idempotency guard, and the whole pipeline has to run end to end offline. So ADK owns the model calls and the agent definitions; durable state and effects stay where they can be made idempotent.

No agent in the fleet binds tools. Every capability an agent has — reading a chart, resolving a citation, writing to the case — is a Python call made by our code around the model call, which is what lets the Cannot column above be enforced rather than merely prompted.

Running under failure

An agent pipeline that retries is an agent pipeline that will do something twice. Every action that is not safely repeatable — submitting an appeal, recording a signature, escalating a level — is claimed through an idempotency guard keyed on case_id:action_type:attempt, with create-only claims and leases, so a redelivered Pub/Sub message resumes rather than repeats. The subscription has a dead-letter topic. Every agent invocation emits an OpenTelemetry span to Cloud Trace, so a case that went wrong can be walked step by step afterward.

A failed transmission used to leave an approved appeal that nothing could send and nothing could close — a case in a state with no exit. Recovering from that is now an explicit path rather than a manual database edit.

Eight service accounts, one per agent role, so the gateway’s in-code scoping is backed by real identity boundaries wherever the platform can express them.

One platform detail worth recording, because it cost a day. Gemini 3.x is served only from the global endpoint. Every regional endpoint returns 404 while the Model Garden catalogue lists the models as generally available in those regions. Infrastructure stays in us-central1; model calls go to global. The two are configured separately for this reason.
